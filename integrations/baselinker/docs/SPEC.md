# BaseLinker integration specification

The integration uses the official [BaseLinker API](https://api.baselinker.com/): form-encoded POST requests to `https://api.baselinker.com/connector.php` with JSON `parameters`, `method`, and the `X-BLToken` header. Generate a user API token under Account & other → My account → API. No OAuth or connection configuration is required. The documented request limit is 100 requests per minute.

## Available workflows

- Orders: retrieve up to 100 per request; filter by dates, order/status/source/email and original store or external order ID. Optional raw metadata includes custom fields, commissions, Connect data and discounts. Create orders, update selected fields/status, manage line items and set the total paid amount. `idFrom` and `dateConfirmedFrom` remain explicit caller-managed cursors. See [orders](https://api.baselinker.com/index.php?method=getOrders) and [payments](https://api.baselinker.com/index.php?method=setOrderPayment).
- Catalogs: discover inventories, categories, manufacturers, warehouses and price groups. Browse up to 1000 products per page and fetch product details. Create/update/delete products and bulk update stock/prices for up to 1000 products per request. Bulk responses preserve actual counters and per-product warnings. External storage product values retain provider-specific formats. See [catalogs](https://api.baselinker.com/index.php?method=getInventories), [bulk stock](https://api.baselinker.com/index.php?method=updateInventoryProductsStock), and [external storages](https://api.baselinker.com/index.php?method=getExternalStoragesList).
- Couriers: discover active couriers, API accounts and form fields; inspect order shipments and status history (up to 100 packages); create courier API or manual shipments. Supply exact courier `package_fields` IDs through each package's `fields`; legacy `sizeX/sizeY/sizeZ` transport is retained for saved calls. Download labels as files using shipment ID or tracking number. See [courier forms](https://api.baselinker.com/index.php?method=getCourierFields), [shipment creation](https://api.baselinker.com/index.php?method=createPackage), and [labels](https://api.baselinker.com/index.php?method=getLabel).
- Returns: list returns, discover return statuses/reasons and create returns with documented status/date/currency/refunded and item fields. Legacy `reasonId`, update and delete requests are retained; current documentation does not establish support for those legacy requests. Confirm their behavior on the target account before using them. See [create return](https://api.baselinker.com/index.php?method=addOrderReturn) and [return fields](https://api.baselinker.com/index.php?method=setOrderReturnFields).
- Order journal: read events from the last three days with optional event types, order ID and log cursor. Enable this feature in account API settings. No polling trigger is registered. See [journal](https://api.baselinker.com/index.php?method=getJournalList).

## Behavior and limits

Provider `ERROR` envelopes, including HTTP 200 failures, and HTTP failures become structured service errors. Returned optional/raw values retain provider nulls and sparse fields. Existing typed order/status fields keep their established schemas and use actual provider values without invented defaults.

The API index exposes no suitable current-user/profile endpoint, so no identity tool is claimed. Invoices, receipts, procurement, warehouse documents, supplier management, parcel pickup requests and webhook/polling automation are not registered tools. Token validity, real writes, courier label delivery and account-specific behavior require live verification.
