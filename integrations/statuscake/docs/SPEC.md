# StatusCake API coverage

StatusCake uses account API bearer tokens in the Authorization header, over HTTPS at `https://api.statuscake.com/v1`. The implemented API covers all six monitoring/resource families and both location endpoints. The official reference documents no suitable current-user identity endpoint; no unsupported identity request is made. Configuration has no account/resource identifiers.

The 33 retained tools cover uptime, page-speed, SSL and heartbeat check CRUD; contact-group CRUD; maintenance-window CRUD; uptime runs/periods/alerts; page-speed history; and uptime/page-speed location discovery. All original keys, number/string input types, enum values and optional fields remain. Additive inputs support URL updates and cheaper uptime/heartbeat collection queries. No automatic event subscriptions or replacement triggers are implemented.

Collection tools return provider pagination metadata and `nextPage`. Limits are 1–100. History tools accept RFC3339 or UNIX-seconds strings and convert them to the provider's UNIX-time parameters. Their legacy page input accepts only the first page: continuation uses `nextBefore` and provider links rather than an unsupported page number. Page-speed history retains provider aggregate metadata and any HAR/report links as record metadata; no file export is generated by these tools.

Writes use URL-encoded forms, including bracketed arrays. An explicit empty array clears the field; false query flags are omitted because matchany/nouptime use presence semantics. Page-speed locationIso maps to `region`. Page-size thresholds use the provider's KB unit, while load thresholds use milliseconds. Uptime statusCodes maps to `status_codes_csv`. SSL creation requires exactly three alertAt integer day values at runtime while keeping the existing optional schema. Legacy tags inputs on page-speed/SSL tools remain present but produce a clear unsupported-field error because the current API does not document them.

Maintenance schedules use the supplied IANA timezone; the provider ignores RFC3339 UTC offsets and interprets the date/clock components as local time. Creation requires an explicit target test or tag. Partial schedule updates validate the merged schedule while sending only supplied changes. Contact-group ping URLs use HTTP GET, not an invented POST webhook contract.

The client validates collection/detail/create/history envelopes and documented 204 no-content writes. Missing creation IDs or malformed responses fail rather than claim success. Validation and provider errors are ServiceError; HTTP timeout, fixed-host redirect suppression, token/password sanitization and provider field diagnostics are configured. Rate limits are account-wide; callers should handle 429 without assuming a failed write is safe to repeat.

Official sources: [API reference and downloadable specification](https://developers.statuscake.com/api/), [authentication](https://developers.statuscake.com/guides/api/authentication/), [form parameters and empty arrays](https://developers.statuscake.com/guides/api/parameters/), [errors](https://developers.statuscake.com/guides/api/errors/), [rate limits](https://developers.statuscake.com/guides/api/ratelimiting/).
