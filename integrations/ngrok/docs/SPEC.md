# ngrok API integration

Verified against the current [API overview](https://ngrok.com/docs/api) and [official OpenAPI specification](https://github.com/ngrok/ngrok-openapi/blob/main/ngrok.yaml) on 2026-10-05.

Management requests use HTTPS at `https://api.ngrok.com`, a bearer API key, `Ngrok-Version: 2` and JSON. Agent authtokens serve a different purpose and cannot replace the API key. There is no suitable documented account identity endpoint in this management API; application users are downstream application users, not the authenticated account owner.

The integration preserves 72 existing tools and adds `get_tunnel_session` for verifying an agent’s identity, metadata and credential before lifecycle commands. It covers cloud endpoint CRUD, endpoint CEL filtering and pooling, reserved domain and TCP address CRUD, tunnel inspection, agent session listing/inspection/restart/stop, IP policies and rules, API keys and authtokens, uploaded TLS certificates, X.509 CAs, event subscriptions and destinations, service users through the existing bot-user tool keys, vaults/secrets, SSH credentials and SSH CAs. Host/user SSH certificate issuance, agent-side tunnel creation, application IAM, IP restrictions and AI Gateway administration are outside this surface. The existing bot-user tool keys call the current Service Users API, whose account identity and name/active fields match the previous Bot Users contract. The provider retains Tunnels as a deprecated read API; existing tunnel tools remain for compatibility.

All list tools accept `beforeId` and `limit` (a whole number from 1 to 100), return `nextPageUri`, and optionally accept that complete continuation URL on the same list endpoint. Endpoint listing additionally supports the documented CEL `filter`. A continuation URL must be used without other pagination/filter arguments.

Cloud endpoint creation requires a traffic policy at execution. The legacy optional input field remains optional in its schema. Public bindings open internet ingress; internal endpoints use an `.internal` URL with `internal` bindings. Endpoint update/delete can change live routing. Session commands are asynchronous: a successful response confirms submission, and a restarted agent reconnects under a new session ID. Restart is unsupported on Windows.

New API-key and authtoken values retain their one-time creation outputs; later reads return no token. Secret values and private certificate keys are never returned. Event destination configuration preserves routing fields while redacting stored cloud-provider credentials. Destination creation alone does not activate delivery; associating it with an event subscription does. Supported target properties are Kinesis, Firehose, CloudWatch Logs, Datadog and Azure Logs Ingestion. The OpenAPI target description mentions S3, but its actual schema has no S3 target; S3 delivery is supported through Firehose rather than an invented direct target.

Tools return configuration and certificate metadata rather than downloadable files. There is no export/download operation requiring a file-delivery mechanism or expiring URL renewal. Event subscriptions send events to external destinations and do not create arbitrary webhook receivers.
