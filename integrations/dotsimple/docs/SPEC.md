# DotSimple API integration

The integration uses workspace-scoped Bearer-token requests to `https://app.dotsimple.io/app/api/{workspaceUuid}`. Tokens are generated by the user and can expire; the public API reference documents no OAuth refresh flow. See [token setup](https://help.dotsimple.io/en/articles/64-create-access-token).

Workspace selection is an optional tool input. An existing or newly configured optional default workspace is used when the tool input is absent. The documented [workspace URL](https://help.dotsimple.io/en/articles/159-chrome-extension) supplies the ID; the public reference exposes no workspace discovery or current-user endpoint.

| Area | Tools | Official reference |
| --- | --- | --- |
| Posts | create_post, update_post, get_post, list_posts, schedule_post, delete_posts | [Posts](https://help.dotsimple.io/en/articles/68-posts) |
| Connected accounts | list_accounts, get_account | [Accounts](https://help.dotsimple.io/en/articles/65-accounts) |
| Media | list_media, get_media_file, upload_media, delete_media_files | [Media files](https://help.dotsimple.io/en/articles/67-media-files) |
| Tags | create_tag, list_tags, get_tag, delete_tag | [Tags](https://help.dotsimple.io/en/articles/66-tags) |
| Legacy listings | list_reports, list_autoresponders | Not present in the current public reference; retained for existing connections. |

`get_media_file` preserves the provider URL and metadata and makes a returned media URL available for download. Media IDs returned as numeric strings are normalized to the existing numeric output type. Uploads use binary multipart form data derived from Base64 input, without fetching remote URLs.

The public reference has inconsistencies: the create-post section is headed POST but its Method line says GET, and tag deletion omits `/app` from its otherwise workspace-scoped base path. Existing POST creation and `/app/api/` tag deletion requests are retained pending provider confirmation. Existing scheduling flags on updates and DELETE request bodies are preserved.

HTTP failures use provider error details. Explicit failure envelopes in successful HTTP responses are also rejected. Missing collection payloads fail clearly instead of appearing as empty results. No webhook registration protocol is documented in the current public API reference; no triggers are registered.
