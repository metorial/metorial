# Fillout Forms API coverage

The integration retains `list_forms`, `get_form`, `list_submissions`, `get_submission`, `create_submission`, and `delete_submission`. Existing input keys/types remain; optional URL-parameter names and generated-document selection are additive. Native tags, choice options, documents, approvals, and empty quiz objects are preserved. No form creation/update, account identity, OAuth refresh, webhook administration, or broad workflow tools are added.

API routes use `/v1/api/forms`, `/forms/{formId}`, and `/forms/{formId}/submissions[/{submissionId}]`, with exact encoded path identifiers. Lists return native offset paging, totals, and page counts without fabricated cursors. All documented endpoint confirmations are HTTP 200. Imports are capped at ten, reject invalid JSON/duplicate field IDs and invalid timestamps, hydrate the current form before writing, and expose native complete/incomplete receipt counts. A lost response is an uncertain retained effect, not proof of rollback. Exact deletion first verifies the requested submission and reports provider acceptance; independently confirmed absence is tested privately.

Auth preserves `api_key.token`, `oauth`, optional configured `baseUrl`, and native OAuth `base_url` precedence. Only public HTTPS origins without userinfo/path/query are accepted; redirects and raw transport ancestry are suppressed. Current official OAuth docs do not specify expiry, refresh, scopes, or verified account identity. Self-hosted origins are documented; regional SDK origins are US/EU/Canada. Response credentials reflected in ordinary strings/keys are redacted. Shared internal trace capture is outside the local adapter boundary; universal logging privacy is not claimed.

Generated document URLs come only from an exact submission's native `documents` collection. No bearer is sent to those links, no expiry or renewal API is fabricated, and unknown-expiry links are read into bounded content with timeout, redirect refusal, size validation, stream cancellation and known credential screening. Up to twenty selected documents share a 64 MiB total limit. Unsupported or authenticated links fail with guidance to retrieve current submission metadata. Question file-upload values are preserved without inventing a download contract.

Sources: [REST/auth/rate limits](https://www.fillout.com/help/fillout-rest-api), [forms](https://www.fillout.com/help/api-reference/get-forms), [metadata](https://www.fillout.com/help/api-reference/get-form-metadata), [submission list](https://www.fillout.com/help/api-reference/get-all-submissions), [exact submission](https://www.fillout.com/help/api-reference/get-submission-by-id), [create](https://www.fillout.com/help/api-reference/create-submissions), [delete](https://www.fillout.com/help/api-reference/delete-submission-by-id), [OAuth](https://www.fillout.com/help/oauth-applications), [official SDK](https://github.com/fillout/api-client/tree/main/src). The current create docs supersede the SDK's stale `{id:number}` return annotation. Provider rate limit: five requests per second per API key/account; requests are not automatically retried.
