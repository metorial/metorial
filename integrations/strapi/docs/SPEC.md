# Strapi Content REST API contract

The integration exposes 14 public tools: twelve retained content/media tools, native JWT current-user lookup, and existing media download. It requires an explicitly configured instance and API version; native dynamic models and permissions remain authoritative. No admin discovery, user administration, GraphQL, webhook or trigger capability is advertised.

Collection IDs use Strapi 5 documentId or Strapi 4 numeric IDs written as strings. Records retain each version's native shape. Collection creation sends `{data: fields}`; partial PUT uses the same envelope. Strapi 5 status is a query parameter and defaults to immediate publication. Strapi 4 writes use explicit publishedAt fields, not a fabricated status mapping. Locale omission selects the instance default; deletion does not promise all-locale removal. Version 5 DELETE 204 omits deletedEntry; version 4 retains its native deletion receipt.

Single types use their singular API ID. An absent/null native singleton response fails safely rather than returning an invented record. PUT can create an absent singleton and publish changes unless explicitly draft-only in version 5.

Media metadata uses Upload-plugin bare records and arrays. Current version 5 pagination uses `/api/upload/files/page` and native meta.pagination; version 4 uses `/api/upload/files` with native start/limit. No automatic fallback downloads an entire library. File IDs are exact safe integers. Uploads use real multipart FormData, capped public source downloads without credential forwarding, and unchanged bytes. Empty caption/alt-text updates remain defined values. Empty updates fail before the request.

Existing media delivery uses the native file URL after exact file-ID read and trusted-origin checks. Only documented AWS signed expiry fields are accepted for private signed files. Renewal rereads `/api/upload/files/:id` and verifies unchanged file identity, instance/version/storage origins and credential or independently verified JWT principal. It never invents a signing endpoint, modifies provider URL signatures or follows a changed file to another destination.

API-token profiles describe connection settings without inventing user identity. JWT profiles and get_current_user use native `/api/users/me`; login binds the instance and native user ID. Native JSON-token refresh mode uses `/api/auth/refresh`, persists rotated tokens and verifies the same user. Legacy JWT mode and API tokens do not call a refresh endpoint. Cookie-only refresh sessions and missing rotated tokens require reconnecting.

Transport and malformed-receipt failures produce actionable ServiceError results with no raw transport parent. Auth credentials reflected in native outputs are refused. Internal HTTP trace recording precedes this adapter and has its own privacy boundary; public/error-graph verification does not certify every internal trace consumer.
