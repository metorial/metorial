# Duo Security Admin API coverage

The integration exposes 22 tools: existing user CRUD and association updates, bypass codes, group and phone list/create/delete, administrator list/create/update/delete, protected-application discovery, three log reads and account summary/settings; plus exact group/phone/administrator/application detail through `get_resource`. No Auth API push, Accounts API MSP management, policy writes, token management or directory sync tools are provided. No triggers are registered.

Credentials are an Admin API integration key, secret key and exact account hostname. Commercial and Federal API hosts are supported. New connections explicitly choose recommended v5 HMAC-SHA512 signing and JSON POST bodies. Legacy stored credentials without a signing version retain supported v2 HMAC-SHA1 signing and form bodies; v1 application routes preserve their existing grant compatibility. Explicit v5 mode uses the current v3 application routes. The algorithm uses shared cryptographic/request/error helpers, exact UTF-8 body bytes, RFC3986 parameter encoding and the same signed Date header sent to Duo. Redirects are disabled.

Native `stat` and HTTP status, resource identities, numeric bounds and cursor shapes are checked before reporting success. Lists expose native numeric next offsets; authentication logs use a two-part cursor and millisecond bounds. Existing administrator/telephony `maxtime`/`limit` schema fields remain present but refuse locally because the preserved v1 routes support only `mintime`; no unsupported provider call or retirement claim is invented.

Creation validates required fields and enrollment email before any effect. Unconfirmed enrollment/relationship updates report the retained user ID and prior acknowledgments without claiming rollback or retry safety. Empty profile values can clear supported fields. Bypass generation replaces existing codes. Permanent user deletion retains history and does not immediately delete phones. Native administrator activation links and expiry are returned when available. Application secrets are removed before public transport capture.

Primary sources: [current Admin API](https://duo.com/docs/adminapi), [supported legacy v1 routes](https://duo.com/docs/adminapi-v1), [Federal host guidance](https://duo.com/docs/duo-federal-guide). Native scope, plan, network and clock prerequisites apply. Log availability can lag; finite reads cannot prove complete absence of recent activity. Private mutation scenarios therefore gate before effects rather than promise automatic cleanup.
