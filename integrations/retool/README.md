# Retool

Connect with an organization or Space API access token from Settings > Retool API. Select the read/write scopes needed for each operation. The instance origin belongs to the connection; use your organization or Space domain, or the explicit self-hosted HTTP/HTTPS origin and port. Legacy connections can retain their stored base URL, with the documented legacy cloud API origin as the fallback.

The integration follows the current Retool API v2 reference (deployment version 4.70.0). Self-hosted versions, roles, enabled features and token scopes can differ. Consult the instance’s `/reference` before relying on a capability. No OAuth or current-user identity endpoint is assumed; `get_organization` reads the native organization ID and selected advanced settings.

The 32 tools cover users and existing user attributes, groups and members, app metadata and native deletion, folders, documented permissions, resource/environment metadata, workflow metadata and existing run status, child Spaces, safe source-control settings and API-token metadata. Exact app/resource/workflow reads supplement their discovery lists. No workflow execution, resource credential writes, app deployment, API-token creation or generic administration was added.

`create_app` and `update_app` retain their prior keys and inputs but refuse before dispatch: the current reference has no documented supported route for those app-definition writes. Create or edit an app in Retool and use `list_apps` or `get_app` to read it. No retirement date is claimed. File import/export available in the Retool UI is not represented as an undocumented API export.

User DELETE disables access. App/folder/group/Space deletion reports the native receipt and does not establish permanent erasure of history, trash, caches or prior effects. Permissions revoke removes all direct access to the selected object, including direct children for folders; the retained `accessLevel` input does not limit revocation to a single level. Membership removal validates the native updated-group receipt and the requested member's absence. Removal is sequential: a failure identifies confirmed removals, the uncertain member and users not yet attempted. Read the exact group before retrying. Partial Space updates hydrate the omitted name/domain from an exact fresh read; the API provides no compare-and-swap guarantee.

Native user names, metadata, last-active values and group IDs can be null. These values are preserved rather than replaced with fabricated strings or IDs. Numeric `legacyGroupId` is exposed where the provider returns it. Resource display names and environment default flags use the documented native fields. Unsupported legacy resource access aliases and Query Library `own` access receive actionable validation errors.

Users/apps/resources use native cursor pagination and require the same explicit limit with a continuation token. Folders/workflows have no documented native cursor parameters: the existing limit and token fields now slice a positively complete bounded native inventory locally. Restart if that inventory or connection changes. Incomplete inventories are refused rather than reported as complete. All responses are bounded to 8 MiB; local inventories are bounded to 10,000 items.

Source-control reads omit provider credentials and unsafe URLs. Token reads expose metadata, not token values. Validation and upstream failures use safe messages with HTTP status where available; failed writes can already have taken effect and require an exact read before retrying.

The private verification suite is active. Read checks require independently pinned organization/token/instance and object snapshots. Folder writes require explicit isolated-account authorization, a pinned parent and full permissions/child inventories, no external automation or concurrent changes, and acceptance of retained history/manual reconciliation. Personnel, group, permission, app and Space destructive lifecycles are gated where complete ownership/effect proof is unavailable. Local verification does not establish live provider acceptance.
