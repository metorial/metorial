# Canva REST v1 integration

The current official REST documentation unifies the former Connect API under the Canva Developers SDK. This package uses `https://api.canva.com/rest/v1` and the documented OAuth authorization-code flow with S256 PKCE, Basic-authenticated token exchange and single-use rotating refresh tokens. It retains the OAuth method key and legacy token fields. New auth outputs also retain verified native user/team IDs and original client binding; unbound stored access tokens continue working, but renewal requires reconnect.

The public surface contains 25 tools: user/team profile; exact asset read/update/delete, public URL upload and URL-upload status; design list/read/create, export/status and URL import/status; folder read/create/rename/delete/list/move; comment create/reply and thread/reply-page read; brand template list/read/dataset and autofill/status. All 23 original keys remain. Binary import status is explicitly available through `sourceType: "binary"`; omitted source type selects the corrected URL workflow.

URL upload is a preview API, including the documented public-app review restriction and 100MB URL video limit. The binary upload endpoint has a different payload and is not synthesized here. Brand template and autofill availability depend on native plan and dataset requirements, not an Enterprise-only assumption. Unknown autofill keys are refused before writing because Canva otherwise skips them.

Exports retain the original URL output and return downloadable files without API authorization headers. URLs expire 24 hours after completion; no absolute expiration is fabricated when polling an old job, and no undocumented renewal/re-export action is registered. Pages are one-based; incompatible format options and missing required qualities fail before export creation.

Native200 read/write and204 deletion/move acknowledgments, exact returned resource/job IDs, native DTOs and continuation tokens are validated. Image summaries in folder listings do not invent owners. Comment author IDs and content/assignment fields are read from their documented nesting. Errors are parent-free service failures at the client boundary; known connection credential reflections are refused in requests and results. Shared internal HTTP capture occurs before this response boundary and has a separate encoded-reflection limitation.

No unsupported resize, folder permissions, broad administration or trigger claims are made. Private scenarios require independently controlled fixtures and original connection binding; irreversible/retained design, comment and folder effects remain gated where this surface cannot observe and reverse complete associated state. Live execution is unverified.

Primary sources: [OpenAPI](https://www.canva.dev/sources/connect/api/latest/api.yml), [authentication](https://www.canva.dev/docs/apps/rest-apis/authentication/), [URL uploads](https://www.canva.dev/docs/apps/rest-apis/reference/assets/create-url-asset-upload-job/), [URL imports](https://www.canva.dev/docs/apps/rest-apis/reference/design-imports/create-url-import-job/), [export jobs](https://www.canva.dev/docs/apps/rest-apis/reference/exports/get-design-export-job/), [autofill](https://www.canva.dev/docs/apps/rest-apis/reference/autofills/create-design-autofill-job/).
