# Bitwarden organization API contract

The integration targets only the cloud organization Public API at `https://api.bitwarden.com/public` or `https://api.bitwarden.eu/public`. Authentication POSTs form-encoded `grant_type=client_credentials`, `scope=api.organization`, organization client ID and client secret to the matching `/connect/token` identity host. The documented token response may omit scope; an explicitly returned scope must still be api.organization. The native access token and exact returned expiry are persisted; renewal is bound to original organization credentials and region. No refresh token, person/self endpoint or local vault is invented.

Current API fidelity is based on the OpenAPI 3.0.4 document labeled `latest` embedded in the official documentation page, retrieved on 2026-10-06. Current server source was separately checked at commit `9030c42bf7d8f9ac2ff9fee85c39588d5eb81499`. A future self-hosted or older deployment may differ; this integration does not silently reinterpret unsupported legacy fields or send credentials to arbitrary hosts.

| Capability | Native contract |
| --- | --- |
| Members | GET/POST `/members`; GET/PUT/DELETE `/members/{UUID}`; GET/PUT group IDs; POST reinvite/revoke/restore. Removal affects organization membership, not the user's account. |
| Groups | GET/POST `/groups`; GET/PUT/DELETE `/groups/{UUID}`; GET/PUT member IDs. PUT replaces omitted fields. Compound group/member assignment is sequential and may leave partial effects. |
| Collections | GET list/detail, PUT permissions and DELETE exact UUID. No native creation route. Names and vault contents are not exposed. |
| Policies | GET list, GET/PUT `/policies/{numeric type}`. UUID inputs to the retained update tool are uniquely resolved from native list metadata. |
| Events | GET `/events` with native date/filter/cursor behavior; only this documented list is paginated. Acting-user and item selectors cannot be combined without native precedence silently ignoring one. |
| Directory import | POST `/organization/import`; native empty 200 acknowledgment. Counts are submitted entries; invitations/removals/overwrite and retained audit effects are not assumed reversible. |

Current member roles are Owner 0, Admin 1, User 2 and Custom 4. The current published models omit accessAll. Legacy schema fields and keys are retained, with local refusals for true/unsupported Manager 3 and nullable absent output flags. Omitted association sets, hidePasswords/manage flags and existing Custom permissions are preserved when visible. The retained per-association readOnly input keeps its legacy false default. Omitted native fields remain unknown and cause a pre-effect refusal when required to preserve a replacement PUT; explicit complete replacements remain supported. Read outputs expose optional association/configuration availability flags without changing existing field types. Explicit association arrays and permissions objects mean full replacement. Native mutation receipts must match the requested ID and submitted state, and a group is read back before a dependent membership write; incomplete or malformed responses refuse further actions.

List inventories require complete native responses and unique exact UUIDs. Events are limited to 100 pages/10,000 records with repeated-cursor refusal; transport response size is bounded to 4 MiB. No silent truncation or redirect following is allowed. Private creation never sends an unnecessary membership replacement before baseline-ID enrollment; cleanup requires an actual empty native collection-association array, not an omitted/null field. Unknown outcome or ownership remains retained for manual reconciliation, with no invented rollback. Configured authentication credential reflections are screened before the shared HTTP trace adapter, including tested encoded forms; this is not broad censorship of user-requested secret data or a universal claim about all runtime diagnostics.
