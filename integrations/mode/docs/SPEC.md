# Mode integration

This integration targets the documented Mode API at `https://app.mode.com/api`. Mode is owned by ThoughtSpot; the Mode API remains documented separately from ThoughtSpot REST APIs and Analyst Studio. A paid Mode workspace is required.

Authentication uses HTTP Basic with an API token and secret. Workspace tokens have administrator permissions and cannot clone reports or create invites. Previously issued personal tokens remain usable with the user's permissions. Token, secret and workspace slug are stored in the connection; older connections may supply the slug through legacy configuration. New configuration does not duplicate it. Credential verification uses `/verify`, paired with a scoped private collection read and the documented account representation. Workspace identity is not presented as a token owner's human identity. No token refresh or granular OAuth scopes are invented.

Nineteen tools cover account identification; reports; SQL queries; asynchronous report runs and query-run status; collections; datasets; data-source discovery; SQL definitions; report schedules; membership discovery; and CSV/JSON/PDF result downloads. Seventeen historical keys and schemas are retained, with optional discovery/output metadata added. No triggers are registered.

Lists consume HAL `_embedded` resources and follow only same-origin, same-resource `next_page` links. Original filters and ordering are retained, and contradictory continuation links fail visibly. Explicit pagination returns one page. Cycles and excessive pagination fail visibly. Resource tokens are encoded as path segments. Required action fields, empty updates, numeric IDs and calendar bounds are validated without changing historical schema requiredness. Collection description-only updates hydrate the required existing name. Dataset updates use the documented `report` envelope. Definition SQL/data-source fields follow the official cookbook. Schedule requests use nested `cron`; responses may expose frequency/time-zone and human-readable hour/minute instead. Numeric fields remain nullable when the provider returns display text, which is separately retained.

Run creation is asynchronous (HTTP 202). Accepted execution does not mean success. Report SQL/notebooks and schedules may have billable or notification effects. The documented API has no individual-run cancellation or deletion capability exposed here. Purging results is not used for cleanup.

Downloads read a successful existing report/query run. CSV and JSON support report or query-run results; PDF supports the report run after its notebook is absent or has succeeded. Authenticated content is fetched with a timeout, disabled redirects, a 50 MiB limit and MIME/signature validation. Files are delivered as downloadable results with file and run metadata. Error messages omit provider payloads, SQL, parameters and credential-bearing request details.
